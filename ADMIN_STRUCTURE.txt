SECURITY
--------
Admin role comes from the `role` claim in the JWT's app_metadata, which only
the server can set. It is NOT read from user_metadata and cannot be granted
client-side.

The redirect in _layout.tsx is a UX guard, not the authorization boundary.
Every admin read and write is enforced by Postgres row-level security or by a
service-role Edge Function that re-verifies the claim (admin-profiles,
admin-withdrawals, admin-review-id, admin-verifications-list). Hiding a button
never decides access.

Account status changes require a reason and are written to admin_action_log.


CONVENTIONS
-----------
Theme       Every admin file uses the useAppTheme() token set from lib/themes.
            No hardcoded brand or semantic colours remain; #FFFFFF for text on
            filled buttons and one dark ink for text on amber are deliberate.

States      Loading / empty / error come from AdminUI so they stay consistent.
            An empty state says what is empty and why. A failed refresh over
            existing data degrades to a banner rather than blanking the screen.

Honesty     A value that could not be computed shows an em dash, never a
            defaulted zero. A truncated list says so. An unreadable data source
            is named rather than looking like an empty one. No screen reports
            success for an operation that did not happen.

Paging      Every list is bounded and shows "showing N of M". Rows per page is
            an operator preference read by hooks/useAdminList.ts.

Writes      Money-moving operations stay on their own flows (completion,
            disputes, withdrawal recovery). Bounty status changes are lifecycle
            only and never release escrow.
